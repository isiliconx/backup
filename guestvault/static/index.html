RECOVERY CAPABILITIES

Know what comes back.

  • Files and hidden app profiles
  • Browser databases and saved credential files
  • Linux system configuration and installed files
  • File permissions and supported metadata
Guest backups have limits

Running apps, memory, VM hardware and live connections require host checkpoints. Online logins can expire after a restore.

Linux OS recovery needs a rescue environment. Windows system-image recovery needs Windows Recovery. macOS file backups require separate OS installation and application recovery.

Import a backup

Choose your saved file and unlock its contents.

Recovery reads directly from the repository. It does not download or unpack a complete portable file. Storage-provider credentials must be available to GuestVault.

Use an empty folder to recover files, or an empty mounted Linux root in a rescue environment. GuestVault refuses to overwrite your running OS or an existing folder’s files.

BEFORE YOU RESTORE

Rebuild from a safe place.

  1. Choose your cloud repository and backup date, or download your portable .vmbackup file.
  2. Use the same operating system and run with administrator privileges to preserve ownership.
  3. Verify the archive, then restore to an empty destination.
  4. For full Linux recovery, boot rescue media and restore onto the prepared system disk.
A fresh OS is still running

Replacing its active system files cannot safely recreate the old machine. Use the recovery guide in the GitHub repository for the final OS recovery steps.
